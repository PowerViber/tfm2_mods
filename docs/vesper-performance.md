# Vesper performance and lossless assets

All 1,132 shipped animations compare exactly by decoded RGBA pixels, frame dimensions, order and duration. Full decoded storage falls from 187,349,936 to 173,187,936 bytes (13.51 MiB saved). The largest atlas is 4 MiB. Per-rank outfit sheets and separate HUD/mark groups reduce the cost of first touching a large sheet. Identical quantized frames share rectangles; no frame, effect, colour, anchor or lifetime is removed.

`Claude outputs/vesper/quantization-reference.zip` locks the original palette result when the source canvas hash is unchanged. This prevents Pillow octree implementation differences from changing colours. The drawing pipeline still runs; changing its pixels invalidates the cached reference. `tools/verify-vesper-animation-equivalence.py` compares against the baseline animation hashes from commit `30f2969`, so a changed source cannot silently become a lossless update.

Native visual selection caches unchanged descriptions. Zone publication caches equivalent rounded geometry and expiry. The per-instance opt-in profiler records planning, core, snapshot, host command, visual sync, effect tags, same-tick signature repetitions and estimated overlaps. It audits repeated emissions without suppressing any. Samples and logs are bounded; simulations, owners and replay copies own separate profiling state. The core observer regression verifies unchanged commands and gameplay RNG across all eight mastery ranks.

Enable `perf.flag` beside the installed DLL before launching the game. `vesper_perf_log.txt` reports separate seed/instance/origin/owner contexts. `first_asset_bytes` counts new atlas references for that passive instance; it does **not** measure the renderer's process-wide texture cache or upload time. The estimated active-effect count is capped at 512 for diagnostics.

The captured new-build profile contains Unknown-origin and ServerPresim windows, summarized in `vesper-host-profile.json`. Unknown-origin core maximum was 1.479 ms and the worst ten-second-window core p95 was 0.0433 ms; these are hook measurements, not rendered frame times. No comparable old-build or cold/warm renderer baseline exists. First-use rendering, simultaneous renewals, packets, Kidnap, death/replay and crowded visible fights remain acceptance work. The reported sudden freezes are **not yet accepted as fixed**.
